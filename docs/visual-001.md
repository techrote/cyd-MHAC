# CYD-VISUAL-001 — provisional audiovisual performance candidate

Refs #3. Stacked on audio PR #2 exact input 805043539d66b3f5caa60595c012e10b86142c50. v1 contract accepted without modification. The visual target supplies both strong hooks and a single UI producer. Default audio-only target keeps its serial diagnostics; choose the separate config explicitly.

## Operation (candidate; not yet on physical hardware)

Boot muted. Tap top-right square to unmute, release, touch and drag elsewhere to sound. X is exponential pitch, Y phase-modulation timbre (higher on screen = higher Y). Two samples required for gate-on; release immediate on next observed up. Top-left square cycles Resonance (interference), Prism (folded phase lattice), Glyph (abstract procedural motifs). A corner press consumes the entire gesture. BOOT mutes; release then explicitly unmute. Stale held samples >100 ms mute on next UI tick; an actual stuck UI is not covered by this cooperative timeout. A DMA write failure latches mute until reboot. No latch or multitouch. Provisional raw calibration endpoints/pressure threshold follow the exact Diviner hardware adapter; per-device calibration wizard, nonblocking independent watchdog, and measured latency are future work.

All modes use actual v1 peak and oscillator phase, plus control state and procedural time. Phase is a sampled block-boundary quantity, not a waveform; do not claim these are oscilloscopes or decoded semantic symbols. Glyph is creative analogy only. Snapshot is coherent but has no wall-clock timestamp in v1; frame tick is UI time. Frames hold one snapshot through all strips, not synced to audio.

## Resource design

One 320×8 RGB565 strip = 5120 bytes (not including driver overhead), 30 strips per frame, no frame buffer, no per-pixel float/trig or explicit dynamic allocation. Render one strip per Arduino loop; touch poll nominally every 8 ms, UI delay and transfer may extend it. Hardware target begins at 2×2 shading (160×120 evaluated pixels) and lowers to 4×4 if measured whole frame exceeds 85 ms or strip exceeds 5 ms. Revert after 60 fast frames under the lower thresholds. Full LCD still receives 153600 bytes/frame; this reduces compute, NOT SPI bytes. At ideal 40 MHz, raw payload alone takes 30.72 ms/frame; real throughput and contention unmeasured. The audio task never waits on rendering. Diagnostic serial reports frame/strip duration, quality and audio DMA success/error counters when silent and UART space allows; these counters are not proof of no underruns.
